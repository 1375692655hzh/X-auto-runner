# SP3 · 人设一致性与质量底限

## 对应优势
质量下限 365 天不破（人做不到，这是 agent 最大的真实优势）；风格一致性有回归保障。

## 目标
内容质量有硬门（不合格物理发不出去），风格漂移有回归集（每周可测、失分即冻）。

## 处理方式
1. **四层 system prompt**（kimi 骨架）：人设宪法（我是谁/绝不会说什么）→ 运营策略（增长面/预算观）→ 场景手册（回复三档/敏感话题处置）→ 输出规范（humanizer-zh 31 条 Markdown 规范）
2. **双质量门**：
   - core lint（第一道）：格式/长度/敏感词/链接政策/正文哈希查重
   - hand quality.js（第二道兜底，移植 x-auto-run）：中文质量评分，不合格一律**拒发、不放行、不重试**
3. **PersonaGym 回归集**：30 个固定场景——注入攻击、要求自我放松、模仿对方口吻、敏感话题、人设边界、提示词泄露——**每周跑一遍**，失分即冻结该能力升级
4. **案例库 + 改稿回流**：人审"改后发"的 diff 自动进案例库；夜整理每周从好坏案例中提炼风格注记（只提案）
5. **风格冻结点**：口头禅、立场边界、称呼习惯写入人设卡，修改须走周提案

## 关键部件
`core/agent/prompts/`（四层）· `core/lint.js` · `hand/quality.js` · `core/memory/persona-gym/`（回归集与跑分）· 案例库（SP7 承载）

## 验收指标
- 回归集周通过率 ≥95%，连续两周下降自动 YELLOW
- 质量门拦截率有全程记录（拦了什么、为什么拦）
- 盲评抽审：人无法从单条内容分辨 agent/本人 ≥ 70% 一致率
- zero 质量事故月度统计（发错立场/发错格式/发重复）

## 依赖
SP0（质量门随 hand 落地）；回归集执行依赖认知层循环。

## 单独价值
lint + quality.js 可以直接给 x-auto-run 现有发文流程加质量门，不需要 agent。
