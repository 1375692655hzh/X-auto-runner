# SP2 · 对话连续性与关系经营

## 对应优势
**记得三个月前跟这个用户说过什么**——互动从"一次性应答"变成"关系经营"。这是 x-auto-run 架构上永远给不了的能力（它连存的地方都没有）。

## 目标
每个对话对象有连续上下文，跟进有节律，关系阶段可度量、可晋升。

## 处理方式
1. **会话线程装配**：mention → 父帖链拉取（read_post 沿 conversation 回溯）→ episode 记忆写入（参与者/话题/我方承诺/情绪基调）
2. **画像卡**：每账号一卡——关系阶段、历史话题、语气偏好、价值标签（谁的问题值得认真答）、红线（谁的雷区不碰）；回复前检索注入上下文
3. **跟进事件**：对话中出现"回头告诉你/明天见"类承诺 → 登记 followup_due 唤醒事件（grok WakeEvent）→ 到期作为**刺激**进简报，跟不跟、怎么跟由 agent 裁决（事件不是任务）
4. **关系阶段晋升**：陌生 → 互关 → 常互动 → 拥护者；每阶段解锁不同回复档位与预算倾斜（互关后权重 ×4，是算法给的复利）
5. **mention 合并纪律**：多个普通 mention 合并为一次唤醒刺激，不强制逐条回复；自家号/实质提问的区别对待进画像而非硬规则

## 关键部件
`core/memory/`（episode 读写/MemoryPort）· 画像卡 schema 与检索 · `core/wake/followup` · 线程装配器（依赖 SP0 read_post 链式调用）

## 验收指标
- 上下文召回抽审：回复是否用上了已知背景（历史话题/承诺/偏好）≥90%
- 跟进兑现率：登记的 followup 有多少在合理时间内被提案跟进
- 关系阶段迁移统计：每周期陌生→互关、互关→常互动的数量
- 反向指标：张冠李戴率（把 A 的事记成 B）= 0

## 依赖
SP0 + SP1 + SP7（三层记忆是它的存储底座）。

## 单独价值
即使只为"把 x-auto-run 跑下来的互动历史变成关系资产"也值得——从第一天起每条互动都在积累。

## 方案出处
kimi-k3 三层记忆/MemoryPort/anti-drift · grok-4.7 WakeEvent followup_due/叙事分区 · glm-5.3 用户画像
