# SP5 · 数据回收与自改进闭环

## 对应优势
系统自己看着数据提优化案——调参从"你天天盯"降到"每周半小时批复"；内容质量随时间**有方向地**演进而不是随机波动。

## 目标
效果数据自动回流，夜整理每周产出有数据依据的调参提案，你只做批复。

## 处理方式
1. **fxtwitter 采样工人**（确定性，不叫醒模型）：每帖 T+2/8/24/48h 拉 `api.fxtwitter.com/2/status/{id}`——likes/reposts/quotes/replies 稳定可信；**views 不可靠不采信**；结果落 SQLite post_metrics
2. **夜整理**（每日 23:20±15min，core 内部调度 + schtasks 23:40 兜底）：日记 / 案例提案 / 画像提案 / 明日倾向——**只提案不动线上**
3. **周报 + 周调参提案**（周日批，≤30 分钟）：
   - 哪类内容互动率分档（附各档数据）
   - 哪个时段/哪种回复档位效果好
   - 预算再分配建议（原创 vs 回复 vs 浏览）
   - 人设措辞微调建议（附案例）
   - 全部附数据依据，**简报只陈述事实不含指令**（反退化条款）
4. **A/B 纪律**：小步、可回滚、每实验有假设和判读标准；同一时间在跑的实验 ≤2 个
5. **采纳闭环**：提案采纳 → 4 周后自动生成前后对比 → 结果回写案例库

## 关键部件
`core/workers/fxtwitter-sampler.js` · `core/reflect/`（夜整理）· `core/report/weekly.js` · post_metrics 表 · 提案队列（复用 SP6 票据面）

## 验收指标
- 快照完整率 ≥95%（48h 四点采样齐全）
- 每周 ≥1 条有数据依据的提案（连续零提案 = 闭环失效信号）
- 你的调参时间 ≤30min/周（设计的北极星指标）
- 采纳提案的 4 周对比自动生成率 100%

## 依赖
SP0（工人/夜整理部分）；提案质量依赖 SP7 案例库；**工人+周报可先行独立落地**。

## 单独价值
fxtwitter 采样 + 周报可以先给 x-auto-run 用——它的数据采了但没用起来，这是纯增量。

## 方案出处
