# 优势子项目拆解（九张可独立立项的工程卡）

把五轮 MoA 定稿方向中「相对 x-auto-run 的每项优势」拆成**可单独立项、单独验收、单独结算价值**的项目卡。
每张卡自带：目标 / 处理方式 / 关键部件 / 验收指标 / 依赖 / 单独价值 / 方案出处（docs/moa-round5/）。

## 总原则（继承五轮共识，所有卡共用）

- 认知层做决策，代码做执法；预算是天花板不是 KPI
- 安全真相只有一份（state/，代码独占写）；叙事记忆引用不复制
- **每张卡独立可停**：做到哪张停，已交付卡的价值照常兑现

## 项目清单

| 卡 | 名称 | 对应优势 | 一句话 |
|---|---|---|---|
| SP0 | x-hand 操作层底座 | 地基 | x-auto-run 操作范式重构为 XClient 端口+闸门 |
| SP6 | 票据审批与新场景处置 | 无人工处理率 | 写动作走票据异步审批，你的时间随信用递减 |
| SP8 | 寿命工程 | 账号活得住 | 熔断/对账/不变量体系化，寿命是复利前提 |
| SP3 | 人设一致性与质量底限 | 质量下限365天不破 | 双质量门 + PersonaGym 回归集 |
| SP4 | 节律拟真 | 时间结构像人 | 心跳分布/打字矩阵/自然延迟，节律不是指纹 |
| SP1 | 回复引擎 | 互动选择精度 | 回谁变成判断题，抢大号前排吃权重红利 |
| SP2 | 对话连续性与关系经营 | 记得聊过什么 | 画像卡+episode 记忆+跟进事件 |
| SP5 | 数据回收与自改进闭环 | 系统自己提优化案 | fxtwitter 回流+夜整理+周调参提案 |
| SP7 | 记忆资产库 | 复利数据资产 | 三层记忆+晋升机制+可迁移 |

## 建议批次

| 批次 | 项目 | 为什么这个顺序 |
|---|---|---|
| 一 | SP0 | 地基，复用率最高（x-auto-run 现成代码 ≥70%） |
| 二 | SP8 SP6 SP3 | 任何写动作之前必须先有：熔断、审批、质量门 |
| 三 | SP4 SP1 | 节律先行（拟真是回复的前提），回复引擎最早兑现 ROI |
| 四 | SP7 SP2 | 记忆库先立（SP2 依赖它），关系经营随后 |
| 五 | SP5 | 闭环收尾——有了前四批的数据才有东西可自改进 |

## 独立性矩阵（哪张卡可以不建 agent、先落回 x-auto-run 单独用）

| 卡 | 无认知层可用？ | 说明 |
|---|---|---|
| SP0 | ✅ | 端口化 + --dry + 闸门化，本身就是 x-auto-run 的工程升级 |
| SP4 | ✅ 全套可移植 | 把 ±25min 抖动升级为全套拟人节律 |
| SP5 | ✅ 采样+周报可移植 | x-auto-run 数据采了没用好，这里用起来 |
| SP8 | ✅ | 它已有雏形，这里是体系化强化 |
| SP3 | 🟡 部分 | quality.js 质量门可移植；回归集依赖认知层循环 |
| SP6 | 🟡 部分 | 可先给 x-auto-run 的 llm.js 文案加人审闸门 |
| SP1 SP2 SP7 | ❌ | 必须有认知层（判断/记忆/画像） |

## KPI 口径（全卡统一，承接内容质量分析结论）

- **先行指标**（质量直接作用、agent 控制得住）：回复导流曝光、互动率、大号前排占据率、回归集通过率
- **结果指标**（只看不管）：粉丝数、月曝光总量
- **底线指标**（一票否决）：安全事故数、质量事故数——永远是 0
