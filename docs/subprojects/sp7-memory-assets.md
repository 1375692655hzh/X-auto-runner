# SP7 · 记忆资产库

## 对应优势
**跑得越久越值钱的复利资产，且可迁移**——x-auto-run 跑一年沉淀的只有去重记录，这里沉淀的是画像、案例、策略。

## 目标
三层记忆 + 画像库 + 案例库，有晋升机制、可备份迁移、可对接外部记忆系统。

## 处理方式
1. **三层结构**：
   - 短期（会话内上下文）
   - 中期（episode 日记：每天发生了什么、跟谁、结果）
   - 长期（案例/策略版本/画像卡）
2. **载体纪律**：SQLite 只装叙事（st/mt/lt 三层 + tickets 主档 + post_metrics），**绝不复制任何安全字段**（预算/去重/熔断/已发未发一切以 state/ 为准）——防止出现第二份安全真相
3. **MemoryPort 可换后端**：接口化设计；**若你现有 agent 的记忆系统是 Python 且想直接复用，走此口对接**——这是整栋建筑保留双栈的唯一正当理由
4. **晋升机制**：episode 重复出现 → 案例；案例验证有效（数据支持）→ 策略版本；全部留痕、可回滚
5. **单向引用**：记忆引用 state/ 事实（"3 月 12 日发过 X"），绝不复制安全判断；画像把某人标"可放宽"闸门也不放宽
6. **导出与迁移**：JSON 快照 + 周备份；迁移演练纳入验收

## 关键部件
`core/memory/`（MemoryPort/st-mt-lt 存储/晋升器）· 画像卡 schema · 案例库 · 备份工人（复用 x-auto-run 04:00 备份形态）

## 验收指标
- 检索命中抽审：给定场景，召回的相关记忆准确率
- 资产增长曲线：episode/案例/画像数量周增统计
- 备份 → 恢复演练通过（丢库重建 ≤30 分钟）
- 单向引用纪律：code review 固定检查项，违例 P0

## 依赖
SP0。SP2（对话连续性）与 SP5（提案质量）都踩在它上面。

## 单独价值
把 x-auto-run 已有的运行历史（去重记录/回复历史）升级为结构化资产的第一步——不需要完整 agent 就能开始积累。
