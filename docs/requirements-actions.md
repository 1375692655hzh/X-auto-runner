## 二、辅助分类

- **云内容**：云端内容产出（已有）、云端互关帖子池（已有）
  - ⚠️ 开放问题：两个"已有"资产的接口形态（API/文件/数据库？）待用户补充后接 P4
- **互动识别 · 互动账号池（需建立）**，四档分级：
  1. 互关关系 + 互关互动历史记录
  2. 大V关系（主脑筛选 + 人工确认）+ 大V互动历史记录
  3. 正常网友（按互动频率分级计数，优先互动计数高的）
  4. 黑名单（人工确认，不互动）
- **AI 运营提醒路由**：
  - 大V回复 → 提醒转人工 BOT（分类：关注/未关注、关注你/未关注你）
  - 互关关系回复 → 无提醒，AI 自动回
  - 账号健康度即时监控 → 出问题转人工 BOT

## 三、本轮确认的设计裁决（2026-10-23 用户拍板）

1. **媒体识别 = 筛选闸 + 理解工具两件**：
   - 检测（有无图/视频）：DOM 层原语（collectPosts 的 hasMedia，x-auto-run 已有此能力），**策略化**——默认"带媒体帖不评论"（用户示例），按动作类型可配
   - 识别（看懂内容）：多模态理解（截图→多模态模型），供原创帖信息库、运营报告、以及未来策略放开时的评论
2. **互关正式纳入**：早期起号刚需、所有使用者初期都要用。推翻 round5 嫁接方案"互关社群不引进"条款；单账号单 VPS 架构不变，互关是账号运营内的业务层
3. **互动关系网**：参考 X Circle（cut-noodle.com/x-circle）公开算法自研 + agent 长期留档（这是 X Circle 做不到的——它即时计算不留档，我们是运营资产）
   - 权重：回复 3 / 引用 2.5 / 提及 1.5 / 转发 1
   - 时间衰减：每 30 天减半（上周比上月重）
   - 双向合并：√(a²+b²)；单向：普通求和（双向对话者比单向更亲近）
   - 数据源：本账号帖+回复、他号提及——由 agent 账本 + fxtwitter 采样天然覆盖，长期沉淀
   - 展示：运营台内嵌（环形图可选），核心是关系账本本身
