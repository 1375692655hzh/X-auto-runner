# 资讯源自动发布 v1（2026-11-02）

## 任务边界

固定信息库只有数据站的 **资讯、精品文章**。调度器负责增量评分和每小时择优；成稿由 `post-original` 场景完成。没有合格增量时允许 0 条，不为凑数降低标准。

- 活跃窗：**06:30–24:00，与浏览器工位同窗**（2026-11-05 统一）。资讯窗优先取 `news_auto.active_window`，缺省跟随 `runtime.active_window`（单一时间真相），配置缺失回退默认 06:30–24:00。窗外不开新小时；早窗内容由 `since` 位置留待开窗后首个小时桶统一评估，不丢失、不积压补发——兼容未来全自动（不会出现"05:00 生产、06:30 集中补发"）。
- 每小时：有合格增量时 1–5 条；硬上限 5 条
- 同事件同小时只留价值最高的一条；普通题材同一来源每小时最多 2 条
- 模型评分失败/漏评：fail-closed，下个 tick 重试，不把漏评当低分
- dry-run 不创建票据；正式写动作仍走 `/execute` 的质量门与审批闸

## 评分（100 分）

| 维度 | 分值 |
|---|---:|
| 信息增量 | 35 |
| 人设匹配 | 25 |
| 事件重要性 | 20 |
| 素材完整度 | 10 |
| 分析提炼空间 | 10 |

`score >= 70`、`publish=true` 且非 N 档才可入选；按分数、题材档、时效排序，取前 5。

## 题材优先级

- **S**：美联储与重大宏观；重大政策/监管/出口管制/关税；足以改变市场预期的特大企业事件。
- **A**：美股科技与 AI 产业链；腾讯、阿里、字节的实质变动；智谱、Kimi、DeepSeek 的模型/开源/价格/商业化/融资/算力变化；有明确数字和催化的异常波动。
- **B**：其他有明确产业或市场增量的科技事件；传统巨头向 AI/机器人延伸；有真实传导路径的其他宏观事件。
- **C**：加密仅重大监管/ETF/立法、稳定币脱锚、大型平台事故/黑客、系统性清算；地缘社会新闻仅中性判断市场传导。
- **N/淘汰**：港股（已移出人设）、日常涨跌、普通分析师评级、小版本与宣传稿、纯观点/营销/广告、未证实传言、普通币价波动、无增量重复。仅复述已知日期的前瞻/预告不算增量；选战、民调、地方博弈和政治背景评论在没有正式政策动作时淘汰。医药/生物科技等赛道外公司即使业绩上调或大涨也不选，除非有明确且实质的 AI/科技产业传导。

## 主体门槛：名企/头部（2026-11-04 新增）

默认只选知名或行业头部企业、主要模型公司、关键平台与供应链主体、央行/监管/主流机构。普通中小企业、冷门公司、小型医疗/生物科技、普通新股IPO不得仅因业绩高增、上市大涨或订单数字大而入选。非知名企业只有素材明确证明其全行业级影响或关键瓶颈地位时才可例外；无法判断行业地位时宁可淘汰。

回归：必贝特 20/N、Insmed 22/N，均不入选；DeepSeek 新模型开源降价 87/A，可入选。

## 增量与去重

同一事件出现官方确认、关键数字更新、指引改变、影响扩大等实质变化时允许跟进；换措辞、重复转载和单纯市场评论不算增量。字节未上市，不得虚构其股价或财务数据。

## 字数与信息完整度

正文不设固定字数目标。账号状态由 `account_status.py` 每 24h 检查并缓存：蓝 V 不检查长度上限，非蓝 V 保持 280 加权上限；查询失败且无缓存时按非蓝 V 保守处理。精简指删除重复和无关内容，不是删除必要事实。成稿前必须内部核对官方表态、关键数字、原因背景、支撑与反向证据，支撑最终分析的事实不得省略。

## 审核信息卡与发布正文分离

每张资讯票保存 `news_detail`：原始标题、来源/栏目/发布时间、素材原文、信息增量、题材档位、评分和入选理由。QQ 回复 `票 <id>` 查看完整信息卡；`票` 只作紧凑待审列表。执行层仍只消费 `payload.text`，原始素材不会被发到 X。

## 纯文本排版（2026-11-03 已上线）

- 最终 X 正文支持自然分段、段间一个空行、短句/列表单换行；不生成 Markdown 加粗/表格/代码围栏。
- `quality.clean()` 统一 CRLF/CR→LF，只压水平空白，3+换行收敛为一个空行；蓝V/非蓝V长度规则不变。
- 人工改稿先按同一 clean 规范入票；执行器只发送已批准票据的规范正文，夹带不同文本会拒绝。
- X 输入校验按 Draft.js 可见文本/块结构还原文本，保持换行敏感；多行不再走已知可能双写的 execCommand 通道。
- 验收：质量门20/20；双段、三段+列表、单段真机 compose 逐字通过，压平负例拒绝，全程未点击发布。诊断证据在云端 `/tmp/multiline-diag.json`。

## QQ 人审编辑台（当前为 review）

- 新待审稿由 QQ 主动推送：“我想发 XXX＋正文”；启动时不补推历史待审，避免旧稿轰炸。
- `发XXX` 或 `发 XXX` 批准发布；`驳XXX` 或 `驳 XXX` 放弃；`票 <id>` 查看素材、立论和审核。
- 可直接对主脑说“把 XXX 改得更自然/删掉第二段/换个角度”。`review_ops.py` 只修改待审票；改稿重新过主脑与双审核，失败保留旧稿，不触发 X 执行。
- 主脑新增 `get_ticket_detail`：票号出现时先读权威票据；“这个/他/刚才那条”按最近主动通知解析，多候选时只确认不乱猜。公司/代码/上市市场/正文以票据为准，对话记忆不作实体证据；工具未成功不得声称已改/已发。
- 回归：在记忆中故意埋入“必贝特/科创板”错误上下文，问 `news-p-20261103-21-1`，主脑仍正确回答 Agility Robotics/AGLT/纳斯达克；无票号问最近通知，可正确解析到 DeepSeek 票。
- 2026-11-03 auto 真发后，运营者因原生阅读质量复核将资讯原创降回 review；auto 只保留为以后显式配置项，当前不自动发布。

## 自由作者制与单道编辑审核（2026-11-03 重构，当前生效）

- 选中后按 `source_id+时间` 重取全文；截断、乱码、标题与正文主体错位的素材禁止成稿。
- 已移除 AnalysisContract、候选角度竞争、固定内容类型、盲评与双审核。作者直接读完整素材，自由决定角度、结构、详略和收尾，也可 SKIP。
- 单道编辑只守事实、独立可读、信息增量、判断边界与账号红线；输出 accept/revise/drop，具体硬伤最多定向修复并复审一次。
- 新票携带 `value_reviews.editor`，不再携带 `analysis_pack`；自然语言改稿直接使用运营者原话，不重新立项。
- 实测：DeepSeek 待审票 `news-p-20261103-20-1` 经自由作者制重写后主体、故障复发、恢复状态与历史背景完整，编辑一次 accept，仍未发布。

## 可靠性与授权（2026-11-03 已落地）

- **Source 位置**：资讯/精品文章分别记录 `last_time`；`since` 负责持续增量，`next_cursor` 只用于当批向旧页完整翻页。评分成功后才推进位置。
- **处置记录**：`state/news-decisions.jsonl` 顺序记录 received → decision → drafted → ticketed/denied；`news-auto` 每拍对账票据状态，补记批准后的 done/failed/unknown。
- **Story**：优先采用数据站 `cluster_id`，否则按“单一公司+事件类型”或事件哈希归并；同小时按 story_id 去重，跨小时重复增量由机器层拦截。
- **源内容一致性**：标题主体必须在正文出现；微软标题/苹果正文等错位素材直接 N 档淘汰。评分另做候选 key+标题头+主体一致性校验，批次串稿自动拆单。
- **恢复**：选中结果先落盘，票据 ID=小时+序号固定；每张票保存后再继续，重启优先恢复未完成小时。复跑验收票数为 4→4。
- **毒素材不堵管（2026-11-05）**：全文超长拿不全/原条目消失属确定性缺陷，抛 `MaterialDefect` 记审计后跳过该条继续；不再当瞬态错误无限重试堵死整个小时及后续所有小时（实测一条 2 万字超长素材曾堵塞流水线 1.5 小时）。API 瞬态失败仍走同票号下拍重试。
- **Mandate**：每票记录 scope、score、story_id、policy_version、prompt_version；`news_auto.mode` 缺省 review。2026-11-03 曾开启资讯源专用 auto，同日经原生阅读质量复核后降回 review；当前不自动发布。
- 若未来再次开启 auto，服务端只接受当前版本、完整素材和 `value_reviews.editor.decision=accept` 的资讯票；旧 review 票不追溯放行，缺审核/窗口外/版本不符均 fail-closed。首个真发验收：https://x.com/WCixot/status/2117531881910710559 （三段排版保留）。

## 提示词权限隔离（2026-11-04）

- **QQ主脑=控制面**：读状态/票据、转达运营者原话、报告真实结果；不直接写正文、不批准、不发布、不决定作者角度。主脑自由正文 `propose_post` 已移除。
- **作者=内容面**：使用独立 `author-system.md`（身份与底线）+ `author-task.md`（素材、当前稿、运营者原话、编辑硬伤）。动态数据全部在 user，不拼 L1/L2 或主脑 system。
- **编辑=底线面**：输入只有素材、正文和近期正文；问题类型仅 fact/standalone/logic/repeat/redline/format，accept 时 issues 必须为空，不得要求内容形态。
- 改票绑定 `base_revision`，作者收到当前正文；锁内复核版本，历史记录旧/新哈希。主脑无真实执行结果却声称已发/已改会被代码拦截；“直接发吧”走固定审批指令，unknown 不再显示为已发布。
- 回归：作者system不含素材/指令/QQ记忆；编辑越权拦截；假发布拦截；有效 AMD 票经一次具体事实修复后 accept，仍 pending_review。

## 独立决策通道（2026-11-04）

- 新增 `llm.decision`：阿里 Token Plan `decision-model-preview`，用于选题评分、名企/头部门槛、帖子值不值得互动等简单判断。

- 阿里通道失败时通过 `fallback_to_default` 回退 default 供应商链；模型可用性和简单决策实测通过。

## 供应商链与熔断（2026-11-05）

- `llm.py` 新增 `fallback_providers`：同通道跨供应商完整 key/端点按序互备。当前 default/analysis/review 为 Kimi 三模型链 → 火山 `deepseek-v4.1-flash`；阿里 DeepSeek 备用 key 已于 2026-11-06 按运营者要求从生产链移除。
- 触发背景：kimi 套餐额度耗尽（全模型 429），主脑 reply 与作者/编辑链同时瘫痪。
- 熔断：401/402/403/404 或全模型 429 判定供应商死亡，熔断 10 分钟内直接跳过；恢复/额度重置后自动回归原顺位（kimi 仍是第一顺位）。
- 429 且还有下家时不再同 key 逐个换模型硬撞（账号级限流换模型无意义），立即 failover；单供应商配置保持逐模型互备不变。
- 实测：kimi 耗尽时首跳 16s（一次 429 尝试+failover，优化前 45.7s），熔断后 1.4s 直达 deepseek。

## 工位暂不可用的批准等待（2026-11-05）

- 浏览器工位活跃窗已由运营者调整为 **06:30–24:00**；资讯调度窗同日统一为同一窗口（见任务边界），生产和执行共用一个时间真相。

- 批准后遇到 `WORKSTATION_DOWN`：不再直接 failed；票据恢复为 approved，intent 标记 requeued，保留预算与批准。
- 生产工位每30秒检查，到 `next_retry_at` 且仍在票据6h有效期内才自动重试；恢复后同票同内容执行。
- 只有确定性未执行才允许重试；unknown、其他执行失败和过期票不自动重试。历史 failed 票不复活。
- QQ 明确回复“已批准，工位暂不可用；有效期内自动重试，未发布”，unknown 仍显示结果不明。
- 本地验收：首次工位失败→approved/requeued→恢复后done；unknown无重试字段。

```bash

python /opt/xar/hand/news_auto.py --dry-run --hours=24
# 正常运行入口（由 xar-news-auto.timer 每5分钟调用）
```

状态：`state/news-auto.json`。每小时运行分钟持久化随机；评分失败不标记完成。调度记录保留 72h，已评 ID 48h，事件记忆 7 天。

## auto 收尾、时效与熔断（2026-11-09 功能补全）

- `/execute` 在 auto 下可能同次返回 `done/failed/unknown/approved`；这些全部作为已有票据结局落账，不再误记 `ticket_error` 重试。只有无业务状态的传输/内部错误才允许下拍恢复。
- auto 授权新增素材年龄：资讯默认 6h、精品文章默认 24h（`news_auto.max_age_hours`）；缺时间、未来时间异常、超龄均回 review。成稿后同 Story 出现新进展也不自动发旧稿。
- `state/news-auto-circuit.json` 记录 auto 熔断：一次 unknown 或连续两次 failed 后停止新的自动授权，保留人工审核；不自动改实例配置。QQ 按熔断原因去重告警；恢复须人工删除该状态文件并核对原因。
- 票据反馈支持结构化驳回标签；日报聚合近 7 天驳回原因、人工改稿、执行结局和发布效果采样。反馈只作证据，不自动改提示词、评分权重或预算。

## 发布与互动功能底座（2026-11-09）

- post 支持 1–4 张本地图片和 `quoted_status_id` 引用；媒体只允许 `/tmp` 下 png/jpg/jpeg，校验大小与魔数。`/dry` 带 `browser=true` 可在真页准备草稿，绝不点击发布。
- 新增 `/read/notifications` 只读入口与 `inbox.py`：统一回复/提及/新关注事件、通知去重和对话归属。人工回复的线程不再自动续回；新关注只生成条件回关待审票。
- `effects.py` 对 done 的 post/reply/comment 做 T+2/8/24/48h FxTwitter 只读采样；无真实结果 ID 时按公开时间线规范正文唯一匹配，无法确认不采样。聚合计数取每 intent 最新时点，避免累计指标重复相加。
- 新能力不改变预算、活跃窗和审批配置；真实发布仍须单独明确验收。

## 开跑（2026-11-09 运营拍板）

- `news_auto.mode: review → auto`：资讯原创全自动直发（时效 6h/24h、unknown/连败熔断、闭环落账同步生效）。配置备份 `instance.yaml.bak-20261109-auto`。
- approval 按 kind 配置：reply/comment/follow=none（互动全自动，质量门与预算帽仍拦截）；post 的 auto 仅由 news_auto 授权路径批准，旧 review 票不追溯放行。
- budget_24h 对齐 x-auto-tool 任务量：post 10 / reply 20 / comment 60 / like 30 / follow 180 / unfollow 0（24h 滚动帽）。
- 回关统一按 x-auto-tool：事件驱动自动回关。注意 x-auto-tool 的 80 评论/180 关注量由其 #互关 关键词搜索引擎供给，本架构互动为通知/关系驱动，实际日量受事件数与种子池约束。

## 停摆事故与修复（2026-11-10）

**事故**：11-06 10:39 起生产线停摆 4 天（11-06~11-09 零产出，运营者追问发现）。链条：11-06 评分失败（LLM 串稿/JSON 解析）→ 按 fail-closed 设计不推进读取位置 → 积压逐日增大 → 11-08 精品文章增量超 8 页上限 → 每拍整拍 sourceFail，资讯源被文章源拖停。

**修复**（均已上线+回归测试）：
- `_fetch_new` 单源隔离：一个源失败只跳过该源，另一源照常评分。
- 翻页超限截断推进：`IncrementalTruncated` 携带已读最新段，截断取新、推进位置、旧段记审计（`source_truncated`）——生产线不再被积压永久锁死。
- `approval: none` 路由修复：免审动作此前不建票，执行段拿不到票 4ms 拒发（开跑当晚 8 个自动回关全败即此因）；现建票+自动批准（`policy:approval-none`），与 auto 同链落账。
- 沉默告警：活跃窗内 6h 无成功节拍且过开局宽限 → QQ 按日告警（`_ops_alerts`）。

**恢复实证**：pos 手动推进清 4 天积压后，11-10 11 点桶 43 候选→入选 5→5 张票全部 `done·新发`（`policy:news-auto` 批准），FxTwitter 核到 5 条真实上线（11:18–11:21）。auto 链路首次完整实证。
