## 结论先行
五份都不能直接套用。共同错误前提：全新中文 AI/科技人设号、单账号、从零冷启动、Python+XActions 侧车+NSSM+SQLite。实际：JS 自写脚本、多大号矩阵给 Owen 加权+社群互关、schtasks/bat/常驻看门狗、state 文件。
**贴合排序：grok-4.7 最贴合（ActionPlan 模型几乎就是 planner/executor 的翻版）> GLM-5.3（不依赖框架、薄循环 200-300 行最易 JS 重写、唯一把"互关好友优先"写进运营语义）> cursor-opus-5.5（部件最丰富但形态最激进，明确反对 planner 产出任务）> gemini-3.8（偏泛，有事实瑕疵）> kimi-k3（体系最重、自称 AI 实体、明文不支持批量互关）。**

## 三处共同的结构性冲突
1. **防骚扰规则会直接废掉 boost**："同一作者 24h 最多 1 次出向、7 天最多 3 次""同一时段不对同一作者既赞又回"——作用到 Owen 身上，加权核心目的就没了。
2. **14 天 warm-up 从零写操作起步**：针对新号；实际用已有大号，节奏是"前 3 天日 1 帖/第 4 天全量/第 7 天复盘"。
3. **"没有人设卡拒绝生成"与预制模板冲突**：互关帖/云帖/预制帖依赖 config.json 模板，不从人设语料自由生成。
一致点：五份都"护栏写在执行代码不在提示词，LLM 不能绕过代码裁决"——与《规范与约束.md》"所有约束已在代码强制执行"同文化，嫁接在理念上无障碍。

## 逐方案要点
- **kimi**：最不贴合。宪法"你是明确标识的 AI 运营实体不冒充真人"与矩阵运营根本冲突；"默认不开放自动关注/不支持批量互关"否定 followers-scan/contacts；栈最重。可吸收：精确事实与 LLM 记忆隔离清单（可直接写进规范："LLM 输出里的计数和是否已发一律不采信，只读 state"）；runaway 上限套 llm.js；uncertain 对账（真实窗口发帖最易"点了发送不确定成功"，特别适用）；PersonaGym 30 场景做 inbox-reply 注入测试。
- **glm**：内核最易移植第二贴合。200-300 行薄循环 JS 重写无门槛；"互关好友的原创帖是最贵的不动产，优先回快回真回"是五份唯一与社群互关 boost 同向；"互关原创帖 reply ×4"从机制上说明矩阵与 Owen 互关再回 Owen 原创帖为何有效。冲突：关注 L0 永远人批、发帖时机运营体自选会破坏 35±5 错峰。让步：时机自主收回（LLM 只决定"本窗口做不做、做哪条"，时刻交给现有时序）；关注改规范内确定性动作；防骚扰按关系类别重写；事件账本换 state/<账号>/ 追加式 jsonl。
- **cursor（自评）**：零件最丰富，哲学上最反对 planner（"心跳事件 schema 禁止 task 字段""简报禁止祈使句"直接否定 planner 产出计划的现有模式）。形态 B 是"以后想让自己的 MoA/ZCode 体系当大脑、x-auto-run 当手"的唯一接法。**bigram 相似度>0.55 拒绝扩展成跨账号版本对矩阵极有价值：两个号同一时段发高度相似文本是最明显的协同指纹**。可吸收：中间件链顺序+四种返回值、跨账号相似度门禁、FakeX 模拟世界=dry-run 增强版、改稿回流案例、行为熵监测进 dashboard。让步：放弃反 planner 纪律（此场景 planner 产出计划是正确形态，LLM 应成为 planner 决策核心而非取消 planner）；写工具不暴露给 LLM（改用提案制）；网关链增加账号感知+"跨账号目标上限"+"跨账号相似度"两层。
- **gemini**：第四。有互关意识（Tier1 互关 30 分钟黄金窗）但 follow 意图枚举里没有、白名单剔除 bulk_follow；"超时免审队列（评分>92 三十分钟无异议自动执行）"用沉默代替规则，与规范优先文化相悖；事实瑕疵（2023 年惩罚值、"headless=new 指纹与有头无异"过于绝对、打包 Chrome userDataDir 迁移——其他方案指出 cookie 与 OS 绑定不能直接搬）；周调参连续值≤15% 无格子化约束，小样本噪声风险高。可吸收：拟人参数对照补强输入脚本；自主收敛规则（连续 2 帖不达阈值拉长间隔）作代码条件规则；每日微复盘作 LLM planner 先验。
- **grok**：最贴合。**ActionPlan 与 planner/executor 同构（"图上不存在 pick_topic/generate/publish 业务节点"=把现有 planner 换 LLM 驱动，executor 不动）**；写操作只在 ActionPlan 由执行节点调用（LLM 不碰浏览器）；确定性工人与模型分离（=content-pull/dashboard/feishu-report 定位）；安静窗即围栏=运营窗；两套真相=state（安全）+insights/contacts（叙事）；"模型名为空拒绝进运营模式但可 dry-run"；Phase 0 三次杀进程演练与 --dry 文化一致；"长期留本机是默认选项"；周 Analyst 格子化提案+自动回滚不经过模型=直接对接"第 7 天复盘"。冲突：明文排除多账号和自动互关（置顶风险写"不含多号轮换"）；信任分长期人审积累与代码强制无人值守不符；warm-up D1-3 零写对大号不适用。让步：operator:main 改"一个内核 N 个账号上下文"，ActionPlan 加 account 字段；关注改规范内确定性额度；LangGraph/SqliteSaver 不引入；防骚扰按关系类别重写（**主号 Owen 单独加权额度单列、矩阵己方号互动额度单列、互关社群适度上限、陌生人沿用 24h≤1/7d≤3**）。

## 嫁接方案（核心图示）
schtasks/bat（早午晚窗）+resident 事件 → planner.js 内新增：situation.js（代码组装各账号态势报告）→ llm-plan（基于 llm.js 输出 ActionPlan JSON 按账号分组，动作只允许：选哪条预制/云帖、回哪条收件箱、对 Owen 哪条帖做什么、本窗口 noop）→ 规范校验（复用现有强制代码+新增跨账号层，被拒动作带原因码写 decisions.jsonl）→ **LLM 失败/超时/JSON 非法回落原确定性 planner** → state/<账号>/plan-YYYYMMDD.json → executor.js（不改：错峰/去重/计数/熔断）→ 真实窗口脚本 → report/feishu（日报附 LLM 决策与理由；第 7 天 LLM 写反思+≤3 项格子化 config 提案，人手改可回滚）。

LLM 第一阶段只接管低风险文本性选择；数量上限/时刻/错峰/关注互关额度/熔断阈值全部留 config 和规范，LLM 不碰。关注互关继续由 contacts/followers-scan 确定性执行，LLM 最多给候选排序建议。
**多账号推荐"一个内核做矩阵级决策，N 份账号上下文"**（不推荐每账号独立 Agent——boost 需跨账号协调：谁回 Owen 新帖、多号不撞同帖、文本不雷同，独立 Agent 无法协调反而易产生同步行为）；新增跨账号规范：同一目标帖矩阵内互动账号数上限+账号间最小间隔、跨账号文本相似度门禁；both 模式 35±5 错峰继续由 executor 确定性随机施加（不可修改的环境法则）。

渐进上线四阶段（复用自己的节奏不搬 warm-up）：P0 影子（LLM planner 只在 dry-run 产计划，与确定性 planner diff 进飞书日报）→ P1 单号单维度（对一账号开放 inbox-reply 或 topic-posts 的 LLM 选择，3 天/第 4 天全量/第 7 天复盘）→ P2 矩阵（both+mutual-post 选择，启用跨账号上限和相似度门禁）→ P3 反思调参（周反思+≤3 项格子化 config 提案+自动回滚父版本）。回退规则：影子封禁命中/验证码/uncertain/账号熔断 → 代码立即回落该账号确定性 planner（="放权慢收权快"，用文件熔断标记实现）。

**指标口径替换**：五份 KPI 是本号单帖 48h 互动中位数；实际应改四个指标——Owen 帖矩阵参与前后互动增量、互关社群净增、**矩阵回复在 Owen 帖下的可见率（幽灵回复和折叠检测——boost 的核心健康指标）**、各账号健康度。fxtwitter 2/24/48h 采样直接用在 Owen 帖上。

**必须写进规范的风险**：X 平台操纵规则明确针对"多个账号协同人为放大互动"。agent 化让文本更多样但**不会降低这类风险**，甚至可能让人误以为"已经足够像真人"。真正起缓解作用的是错峰、跨账号上限、相似度门禁和熔断这些确定性规则。**LLM 层不应被当成风控手段。**
