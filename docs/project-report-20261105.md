# X/Twitter 中文智能运营 Agent 项目汇报

**账号：@WCixot｜报告日期：2026-11-05｜生产状态核验：23:57（CST）**

## 一、项目概述

本项目是一套部署在腾讯云 VPS 上的 X/Twitter 中文账号智能运营系统，目标是形成一个能够持续完成“信息获取—价值判断—中文成稿—审核发布—回复互动—运营反馈—定期升级”的联合运营者。

当前建设重点不是单纯让大模型写几篇帖子，而是建立一条能够长期运行、失败可恢复、过程可审计、人工可接管的任务流水线。系统将内容创作、运营决策和浏览器执行分离，避免同一个模型既写内容、又批准内容、又宣称执行完成。

现阶段资讯原创已具备从数据抓取到人工审批发布的完整闭环，并保留资讯专用 auto 授权机制；**截至本报告核验时，生产配置仍为 review，auto 尚未正式开启。**回复和互动继续采用人工审批。自主运营研究、反馈反哺和定期版本升级机制是下一阶段重点。

## 二、账号定位与内容边界

### 2.1 账号人设

账号定位为中文美股交易观察者，内容强调：

- 把事情讲清楚：主体、事件、时间、数字和当前状态完整；
- 突出有价值的信息增量和可靠分析，而非简单改写标题；
- 自然、务实、冷静，有正常分段和阅读节奏；
- 不冒充投资机构，不提供买卖点、仓位指令或虚构个人操作；
- 不暴露自动化身份，不为了“像帖子”而牺牲事实完整度。

### 2.2 重点选题

1. 美股科技、AI、云计算、半导体和算力产业链；
2. 美联储、重大宏观经济数据和重要流动性变化；
3. 重大政策、监管、出口管制、关税和产业政策；
4. 腾讯、阿里、字节跳动等中国科技公司的实质变化；
5. 智谱、Kimi/月之暗面、DeepSeek 等中国模型公司的模型、开源、价格、商业化和算力变化；
6. 传统科技巨头向 AI、机器人等方向的重要延伸；
7. 加密领域仅保留重大监管、ETF/立法、稳定币脱锚、大型平台事故和系统性风险。

### 2.3 明确排除

- 港股已移出人设；
- 普通涨跌播报、普通分析师评级、小版本更新、营销稿和无增量重复；
- 普通中小企业、冷门公司、小型医疗/生物科技公司、普通 IPO，不因营收高增、上市大涨或订单数字大而入选；
- 非知名企业只有在素材足以证明其全行业影响或关键供应链地位时才可例外；
- 未正式落地的选战、民调、地方政治博弈和单纯事件预告；
- 字节跳动未上市，不得虚构其股价或财务数据。

## 三、项目能抓取什么：五类数据面

本项目的数据采集不是单一“新闻爬虫”，而是由数据站、X 页面、互动关系、账号健康和内部审计五个数据面构成。

### 3.1 数据站：资讯内容的核心信息库

数据站接口为 `https://data.haiwai.ltd`，通过 `/v1/items` 和 `/v1/sources` 访问。数据站适配层本身支持“资讯、精品文章、周期报告、大V文”等类型；**当前资讯自动发布任务只使用“资讯 + 精品文章”两类，作为固定信息库。**

每条素材可读取和保存：

| 字段 | 用途 |
|---|---|
| 素材 ID | 去重、增量读取、任务恢复和审计关联 |
| 标题 | 初步识别事件，成稿前与正文主体交叉核对 |
| 正文及原始长度 | 价值判断和成稿事实依据 |
| 是否截断 | 截断素材必须重取全文，禁止在残缺证据上写作 |
| 来源名称、来源 ID | 来源追溯、全文重取和来源归因 |
| 内容类型 | 区分资讯、精品文章等 |
| 发布时间 | 时效性、增量位置和票据信息卡 |
| 市场标签 | 判断题材与账号人设的匹配度 |
| cluster_id | 同一事件聚合、Story 去重 |
| event_type | 辅助识别事件类别 |
| tickers | 辅助识别相关公司或资产 |
| 原始链接 | 溯源和审核查看 |

**增量抓取机制：**

- 资讯和精品文章分别保存 `last_time` 读取位置；
- `since` 用于持续获得新增内容；
- `next_cursor` 只用于当批向旧页完整翻页，不能误当成未来游标；
- 只有评分成功后才推进位置，失败时下一拍重试；
- 选中素材后，根据 `source_id + 时间` 重取全文；
- 全文乱码、标题与正文主体错位、原条目消失或全文仍无法完整取得时，不进入成稿；
- 确定性素材缺陷会记录审计并跳过，不再让单条坏素材无限重试、堵死后续全部任务。

**主脑查询能力：**运营者可在 QQ 中询问近期新闻、查看数据站来源目录，并通过受限的只读 API 查询工具获取数据。API Key 由服务端注入，不进入模型上下文；查询仅限本站 `/v1/` 白名单 GET 路径。

### 3.2 X 页面内容：用于阅读和互动，不作为资讯事实源

系统通过 Camoufox 浏览器读取 X 页面，主要可获取：

- 首页时间线和 explore 页面中的帖子；
- 帖子 ID、链接、作者、发布时间、正文摘要；
- 是否带图片或视频等媒体；
- 指定帖子的正文和评论；
- 本账号最近原创帖及其下尚未处理的评论；
- 互关成员的最新帖子；
- 页面中的关注/互关状态、按钮和执行反馈。

**当前用途：**寻找本账号帖下需要回复的评论、互关成员新帖和潜在热门互动对象。

**事实边界：**X 时间线阅读服务互动和运营，不与数据站资讯混为同一事实源；资讯成稿只能使用票据中保存的数据站素材。

**当前限制：**

- Feed 摘要有长度限制，完整线程需要按帖子进一步读取；
- 媒体字段目前主要用于“带媒体帖默认不评论”的筛选，不等于已经完成图片/视频语义理解；
- explore 热帖链路曾受 X 页面改版影响，不能将其描述为已稳定恢复的热点趋势系统；
- 互动对象的获取不等于已经形成稳定互动规模。

### 3.3 互动关系数据：账号池与熟络度

互动账号池将账号划分为四档：

1. 互关；
2. 大V，需人工确认；
3. 正常网友；
4. 黑名单，不互动。

系统能够记录：

- 首次发现时间、最近更新时间和关系档位；
- 我方是否关注、对方是否关注；
- 我方回复、评论、点赞次数；
- 对方互动事件数、最近互动时间；
- 互动历史和熟络度；
- 黑名单和人工备注。

熟络度依据累计双向互动次数划分为“陌生、眼熟、老熟人”。同时设置称呼词日限，减少模板化“老师、老哥、大佬”等表达。

**当前生产证据：账号池仅 1 个 normal 账号，没有 mutual 成员。**因此互关串门逻辑虽已存在，但当前没有足够的真实互关对象支撑规模化运行。这是互动运营的实际瓶颈之一。

### 3.4 账号健康与公开运营数据

通过匿名 HTTP 通道和公开资料获取：

- 粉丝数、关注数、累计帖数、账号资料状态；
- 最近帖子、近 24 小时原创帖数量、转发数量；
- 可获取时的阅读量和敏感内容标记；
- 搜索建议限制、搜索限制、幽灵封禁、回复降权等四维限流信号；
- 与历史健康快照相比的粉丝变化。

健康检查失败时标记 unknown，不把“查不到”误判为“健康”。发现明确 suspended 信号时告警并转人工核验。四维限流雷达设有每日调用上限，避免过度探测。

### 3.5 内部运行与模型决策数据

系统持续记录：

- 每条素材的 received、decision、drafted、ticketed、denied、skipped 等处置；
- 票据创建、审批、驳回、过期、执行、失败、重试和终局；
- 每个动作 rolling 24h 额度使用；
- 模型职能、实际模型、输入/输出 token 和失败原因；
- 供应商失效、跨供应商切换和熔断状态；
- 决策模型的输入摘要、答案、置信度、延迟和影子结果；
- QQ 主脑工具调用、真实结果和动作声明拦截；
- 工位、心跳、暂停、熔断和健康状态。

截至核验时，决策日志已有 **229 条**。这些数据是后续“定期考试”和版本迭代的基础，但目前尚未全部转化为自动分析和改进策略。

## 四、资讯自动发布流水线

### 4.1 完整流程

```text
数据站增量抓取
→ 素材清洗与完整性检查
→ 信息增量、人设匹配、事件重要性和名企门槛评分
→ 同小时/跨小时 Story 去重与择优
→ 重取全文
→ 自由作者成稿
→ 单道底线编辑审核
→ 必要时定向修复一次并复审
→ 创建带完整素材和授权信息的票据
→ 人工审批，或满足专用条件时自动批准
→ 浏览器工位执行
→ 发布结果回写、失败恢复和审计
```

### 4.2 选题机制

评分维度为：信息增量 35 分、人设匹配 25 分、事件重要性 20 分、素材完整度 10 分、分析提炼空间 10 分。原则上 `score >= 70`、`publish=true` 且非淘汰档才可进入候选，再按分数、题材档和时效排序。

每个小时允许 0—5 条；**0 条是合法结果，不为完成数量而降低标准。**同一事件同小时只保留价值最高的一条，普通题材同一来源每小时最多 2 条。

调度状态按小时落盘，选中结果先保存，再逐张成稿和开票。进程中断后优先恢复未完成小时，票据 ID 按“小时 + 序号”固定，避免重启后重复开票。

### 4.3 成稿机制

作者采用“静态身份和底线 + 动态任务素材”的分离结构：

- 系统提示词只规定账号身份、事实边界、红线和输出协议；
- 素材、当前稿、近期历史、运营者改稿意见和编辑反馈全部位于用户任务消息；
- 作者根据素材自由决定角度、结构、详略和收尾，可以主动 SKIP；
- 系统提示词不预设内容类型，不要求每篇都长成同一种“快讯”或模板文章。

编辑只检查事实、独立可读、逻辑、重复、红线和格式，不能把自己的文风偏好当硬伤。可修复问题定向修复一次并复审，无法可靠修复则放弃。

### 4.4 来源归因规则

来源处理采用三层规则：

1. 公司公告、财报、电话会、央行和监管文件等官方来源，可保留“据公告、据财报”等中性归因；
2. 路透、彭博、美联社、道琼斯、金融时报、华尔街日报等一线通讯社属于原创新闻源，可保留署名；中文媒体只是转载时，应剥离转载方并归因到原通讯社；
3. 智通财经、财联社快讯、新浪财经等转述型或聚合媒体的署名不进入主笔正文，其评论性内容不作为观点源。

券商研报、SemiAnalysis 等硬核研究机构的判断可以转述为“某机构认为”；阿里、腾讯等市场主体则以公告、财报、高管原话和实际行动作为事实来源。

### 4.5 排版

最终 X 正文支持自然段落、段间空行和列表单换行，不使用 Markdown 加粗、标题、表格或代码围栏。文本清洗、票据保存和浏览器输入采用同一规范，避免审核版本与真实发送版本不一致。

蓝 V 账号不设置固定 280 字上限；非蓝 V 保持加权 280 限制。账号状态查询失败且无缓存时按非蓝 V 保守处理。

## 五、QQ 主脑与人工协同

QQ 主脑是运营控制面，不是公开内容作者，也没有自由发布权限。

### 5.1 已支持的协同方式

- 新待审稿主动推送：“我想发 + 票号 + 正文”；
- `发 <票号>` 批准，`驳 <票号>` 驳回；
- 查看票据详情、原始素材、来源、评分和编辑结论；
- 用自然语言要求“删掉某段、改得更自然、换个角度”；
- 改稿绑定当前票据版本，重新经过作者与底线编辑，不直接发布；
- 查询工位、心跳、额度、暂停和熔断状态；
- 查询近期新闻、数据站来源、今日运营报告；
- 在授权白名单内处理运营者命令。

### 5.2 真实性与权限保护

- 涉及票号、公司和正文时，必须先读取权威票据，不能凭对话记忆猜；
- “这个、他、刚才那条”等指代通过最近通知的票据解析，多候选时不乱猜；
- 没有成功工具结果，不得声称“已改”或“已发”；
- “直接发吧”等高风险指令走固定审批语义，不由模型自由生成发布结果；
- 主脑自由撰写资讯正文并绕开作者/编辑的通道已经移除；
- 决策模型只用于分类、评分和分流，不能改稿、批准、执行或恢复风控状态。

## 六、发布、可靠性与故障恢复

系统实际 X 操作由常驻 Camoufox 浏览器工位完成，采用固定登录状态、浏览器指纹和静态住宅代理。

当前资讯调度与工位统一为 **06:30—24:00**。统一窗口避免未来 auto 在工位未开放时生产一批内容，开窗后集中补发。

核心可靠性机制包括：

- 写动作幂等键，同票最多一次；
- 票据生命周期和时效：post 6 小时，reply/comment 2 小时，like/follow 等更短；
- rolling 24h 动作预算、全局写开关、暂停和熔断；
- 工位不可用时保留已批准票据，在有效期内自动重试；
- unknown 表示结果不明，禁止自动重发，防止重复帖；
- 服务重启后恢复未完成小时和执行状态；
- 坏素材跳过、API 瞬态错误重试、过期票据释放预算。

**边界说明：**现有机制解决的是可靠执行和防重复，不等于已经完成“等待期间内容是否过时”的发布前时效复核；这是 auto 试运行前需要补齐的质量保护。

## 七、模型体系与故障切换

系统按职能划分模型通道，包括成稿、回复、评论、报告、分析和决策等。

当前已建立跨供应商链：

```text
Kimi 主模型及同 Key 模型互备
→ 阿里 DeepSeek
→ 火山 DeepSeek
```

支持：

- 主模型失败后同供应商模型互备；
- 跨供应商完整 Key/端点切换；
- 401/402/403/404 或持续 429 时供应商熔断；
- 熔断期跳过失效供应商，恢复后自动回到原顺位；
- 推理模型思考耗尽输出预算时，同模型提高预算重试；
- 决策通道失败时按配置回退 default 供应商链。

实测中，Kimi 额度耗尽后系统能够切换 DeepSeek；熔断后第二次调用可直连可用供应商。该机制解决“模型不可用导致整个任务停摆”，但不等于不同供应商生成质量已经等价，需要纳入后续质量评估。

## 八、决策模型

阿里 `decision-model-preview` 用于简单结构化判断，支持 choice、noul、score 等问题类型，可返回概率、置信度和延迟。

当前应用：

- 资讯选题和名企门槛的兼容通道评分；
- 原生 System One 的结构化选题影子门；
- QQ 意图、票据指向和风险的影子路由。

**原生结构化门目前仍为 shadow，不参与实际淘汰。**原因是回归中虽能排除部分小公司，也曾误伤 AMD、美联储等有效题材。只有真实样本证明其稳定优于现有链路后，才考虑灰度启用。

## 九、回复与互动能力

系统已经实现以下任务逻辑：

1. 本账号最近原创帖下的评论回复；
2. 简单招呼的模板旁路，复杂评论由模型结合原帖和关系上下文回复；
3. 互关成员新帖串门评论，同成员 7 天冷却，72 小时无新帖不凑数；
4. explore 热帖筛选、价值预判和评论，作者 21 天冷却；
5. 黑名单过滤、媒体帖默认不评论、互动熟络度和称呼配额；
6. 发帖、回复、评论、点赞、关注、取关等浏览器动作原语；
7. 非固定间隔的心跳调度，活跃窗外休眠。

**当前回复和互动仍走人工审批，不应描述为已经实现全自主互动。**互动池规模不足、热帖读取稳定性、回复质量和互动收益均需进一步验证。

## 十、运营报告与自主反馈：当前差距

现有每日运营报告可以汇总粉丝、关注、累计帖数、动作额度、熔断、暂停和健康状态。

但它还不是完整的“自主运营研究系统”。当前缺少：

- 将运营者驳回、改稿和自然语言反馈统一绑定到具体票据；
- 按“选题不相关、非名企、无增量、事实错误、署名、重复、不可读”等原因结构化归档；
- 自动统计任务是否完成、卡在哪里、是否恢复；
- 将高频问题形成定期版本升级材料；
- 用真实结果评估不同模型、选题策略和互动策略；
- 根据采纳率、信息增量和互动收益动态调整任务量。

下一阶段采用“**即时任务反馈 + 定期系统升级**”：

- 运营者反馈立即影响当前稿件、当前票据和后续具体候选约束；
- 主脑不能因一句话立即修改全局提示词、评分权重或自身权限；
- 定期生成考试报告，汇总目标完成、失败恢复、重复犯错和质量变化；
- 由多模型 MoA 研究改进方案，经回归测试、版本审核和灰度验证后上线；
- 主脑不能自行批准并上线自己的系统改造。

## 十三、下一阶段计划

### 第一阶段：资讯 auto 试运行

1. 清理旧规则生成的署名残留票；
2. 增加发布前时效和重复守卫；
3. 增加连续执行异常自动降回 review；
4. 先只开放资讯原创 auto，回复互动继续人工审批；
5. 按真实发布样本检查选题、正文和来源归因，而非只检查服务是否在线。

### 第二阶段：反馈入口与定期考试

1. QQ 驳回、改稿和自然语言评价绑定票据；
2. 建立结构化反馈原因和版本档案；
3. 每日/每周输出目标完成、未完成、卡点、恢复和重复犯错报告；
4. 让反馈即时约束当前及后续具体任务，但不直接修改系统规则。

### 第三阶段：版本化 MoA 升级

1. 定期汇总典型成功/失败案例；
2. 多模型提出选题、成稿和任务分配改进方案；
3. 用固定回放集和真实样本做版本对比；
4. 运营者批准后灰度上线，可回滚；
5. 决策模型只有在影子数据达标后才转为实际门控。

### 第四阶段：扩大自治范围

资讯原创稳定后，再依次验证回复、互关互动和任务量动态分配。每一层独立验收，不因资讯 auto 可运行就默认所有动作都可以无人值守。

## 十四、汇报结论

项目已经越过“模型生成一段文案”的演示阶段，形成了真实部署、持续调度、可审核、可恢复、可切换模型的账号运营系统。当前最有价值的基础不是复杂 Agent 框架，而是数据、内容、权限、执行和审计五层已经连通。

下一阶段的核心目标是：**先证明资讯 auto 能持续做成事，再让每次驳回、修改、失败和发布结果进入可追踪的反馈与版本迭代体系。**互动和自主运营研究应建立在真实任务数据之上，逐步扩大自治，而不是一次性把全部权限交给模型。
