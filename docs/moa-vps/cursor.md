# 来源：Cursor Agent（cursor-grok-4.6-high，--mode plan 只读）· VPS 选型 MoA · 2026-10-23

> 协调方注：价格事实已经 cursor 岗联网交叉核验。原始任务书存 .moa-task-cursor-vps.md。

## 总结论

建议买腾讯云轻量应用服务器，地域选中国香港，镜像选操作系统镜像里的 Ubuntu Server 24.04 LTS，规格选 2核4G / 60GB SSD / 30M 峰值带宽 / 1.5TB 月流量。不额外买流量包，也不走 Windows。

黄金镜像必须是"干净底座"：浏览器 profile、指纹参数、state/ 账本、密钥、SSH 主机密钥都不能进镜像，一律在每台实例首次启动时生成。

单台 VPS 月成本大约 50–90 元（以下单页实时价为准），住宅代理另计。

## ① 镜像路线：选纯操作系统镜像（Ubuntu 24.04 LTS），不选应用镜像和容器镜像

Hermes Agent / OpenClaw / Octop 和本项目是什么关系：没有关系，而且会冲突。它们是别人写好的个人 AI 助手运行时。本项目要跑的是自研 Node.js agent，所以这些镜像对本项目只有一个作用：顺便装好了 Node 和几个系统服务。它们带来的冲突包括：

- 抢 Telegram bot：这些镜像自带 Telegram 网关，会自动启动。同一个 bot token 只能有一个进程拉取消息，两边同时拉会互相报 409 错误、互相踢掉；就算 token 不同，也多出一个不受控的 IM 出口。
- 占资源、占端口、带自启服务：它们常驻的进程、端口和目录结构，和本项目的 resident 进程及看门狗抢内存。4G 内存本来就要留给浏览器。
- 污染黄金镜像：做镜像时会把这些第三方服务一起克隆出去。以后每台机器都带着一个你不维护、不审计的 agent，而且它的升级节奏跟着腾讯云走。
- 省事的地方很少：省掉的只是装 Node 这一步，而这本来就是一条命令的事。

为什么不选 Node.js 应用镜像：Node 版本由镜像决定，没法精确锁版本。用纯系统镜像再自己按版本号装 Node LTS，黄金镜像才可复现。

为什么不选容器镜像（预装 Docker）：架构已经定了"一云一号 + systemd 调度"，整台 VM 本身就是隔离单元，再套一层容器没有收益。反而要额外处理：浏览器在容器里的共享内存（--shm-size）、容器里跑 Xvfb、profile 和 state 的挂载卷、systemd timer 和容器生命周期怎么配合。可复现性已经由黄金镜像解决了。

为什么不选默认的 OpenCloudOS 9：Playwright、Camoufox 和 Chromium 的系统依赖，主要是按 Ubuntu / Debian 测试和写文档的。换成 RHEL 系发行版，就得自己排查缺哪些库、字体怎么装。Debian 12 可以作为备选。

## ② 地域：选中国香港

浏览器流量走住宅代理，所以 VPS 地域只影响下面四件事，香港在其中三件上占优：

- 大陆 SSH 管理：香港到大陆延迟约 30–60ms（三网双程直连），硅谷约 150–250ms 且晚高峰易丢包。香港明显胜出。
- GLM API（open.bigmodel.cn，在境内）：从香港访问是短链路；从美国或日本访问要两次跨境，延迟高、抖动大。香港胜出。
- Telegram API 和 fxtwitter：香港不受大陆网络限制，可以直连。各地域都没问题，算打平。
- VPS 到住宅代理的延迟：这是香港唯一吃亏的一项。如果代理是美国 IP，香港到美国多出约 150–200ms，但它只体现在浏览器页面加载上。agent 本来就按人类节奏浏览，多零点几秒没有业务影响。
- 价格：香港轻量套餐有促销，价格合适。

补充提醒：
- VPS 地域不能出现在浏览器指纹里。浏览器的时区、语言、Accept-Language、地理位置都要跟代理所在地一致，不能跟 VPS 一致。DNS 必须通过代理远程解析：SOCKS5 要开远程 DNS，HTTP 代理本身就由代理端解析。
- 如果晚高峰 SSH 不稳定，可以用腾讯云控制台自带的网页终端（OrcaTerm）兜底，不必为此换地域。（个别香港低配机型可能走普通国际线路，买后先 ping/mtr 验证直连质量，不达标换机型。）

## ③ 规格：2核4G / 60GB / 30M 峰值 / 1.5TB 流量，就是标准单机

内存估算（瓶颈在内存，不在 CPU）：
- 系统本身：约 0.3–0.5G
- 浏览器（Camoufox 或 Chromium）挂着 X 这种重型单页应用长时间运行：约 0.8–1.5G，而且会缓慢涨内存
- Xvfb：约 0.05G
- Node 的 resident + core + IM bot + 看门狗：约 0.3–0.5G
- 合计约 1.5–2.5G

2G 内存会频繁触发内存不足被杀进程，4G 才有余量。还要配三项措施：2G 的 swap 交换文件；用 systemd 的 MemoryMax 给浏览器设内存上限；每 N 小时让浏览器重新开一次页面或上下文，回收泄漏的内存。2 核就够了，峰值只出现在页面渲染和 SQLite 写入时。

系统盘：系统、Node、浏览器程序约 8–10GB，浏览器 profile 加缓存约 1–5GB（建议给缓存设上限），state/、SQLite 和日志每年约 1–3GB。40GB 也够用，60GB 留出快照和备份的余量。

月流量估算（单个浏览器刷 X）：
- 关掉视频自动播放：每天 10 次会话、每次约 50 条推文，日均约 0.1–0.3GB，月均约 3–10GB
- 开着视频自动播放：日均约 1GB，月均约 30GB
- LLM API、Telegram、fxtwitter 的流量可以忽略

结论是 1.5TB 远远用不完，30M 峰值带宽绰绰有余，不需要买流量包。另外轻量服务器只按出方向流量计费，而刷 X 主要是下行流量，计费量会更小（以腾讯云计费说明为准）。真正按流量花钱的是住宅代理。在 X 设置里打开"节省流量"、把视频自动播放设为"从不"，这是真实用户也常见的设置，不构成异常特征。

关于其他套餐：
- 4核8G 约 88 元/月的促销：一般是新用户限购，续费价可能明显上涨。而且它系统盘是 120GB，用它做的镜像只能部署到系统盘不小于 120GB 的套餐上（镜像只能扩盘不能缩盘），会把以后每台克隆机都锁死在高配。不建议拿它当黄金机。
- 锐驰型 200Mbps 不限流量（约 40 元/月起）：本项目用不上"不限流量"。只有当它有 4G 内存的档位、价格也合适时才值得考虑；2G 档不要买；线路质量要另外核实。

## ④ Windows Server：不考虑

- 新架构是 Linux 原生：systemd 调度、Xvfb 或无头运行、Node 和 SQLite，全部按 Linux 设计。
- Windows Server 系统本身就占约 2GB 内存，4G 机器会被吃掉一半；授权费也常让套餐更贵或规格受限。
- 比特浏览器是 GUI 商业客户端，按 profile 收费，需要远程桌面登录操作，不适合无人值守自动化，跟"一云一号 + 指纹浏览器内嵌在 agent 里"的路线不一致。
- Windows 做通用镜像要跑 sysprep，比 Linux 复杂得多。
- 唯一的例外：迁移期如果要保留旧号的比特浏览器环境，就单独开一台机器过渡，不要混进黄金镜像体系。

## ⑤ 黄金镜像骨架：镜像只放干净底座，账号身份全部在首次启动时生成

进镜像的（所有账号一样、可共享的）：
- Ubuntu 24.04 加安全更新基线；SSH 只允许密钥登录、禁止 root 登录，装 fail2ban；建普通运维用户；配 2G swap
- 按版本号锁定的 Node LTS、pnpm，以及固定 commit 或 tag 的 agent 代码和依赖
- 按版本号锁定的浏览器程序（Camoufox 或 rebrowser Chromium）、Xvfb，以及常用字体
- systemd 服务和定时器单元：默认不自动启动，首次启动配置通过后才启用
- journald 和 logrotate 的上限；自动更新只装安全补丁，并排除浏览器和 Node，防止版本漂移导致指纹变化
- 首次启动脚本、空的 state/ 结构和 SQLite 建表脚本（只有结构，没有数据）

绝不能进镜像、每台实例首次启动时生成的：
- 浏览器 profile（cookies、localStorage、IndexedDB、缓存）：黄金机永远不登录真实 X 账号。做镜像前把 profile 目录整个删掉。
- 指纹参数：首次启动时按代理所在地为每个账号生成一份，包括 UA 和平台、屏幕分辨率、WebGL、Canvas 和音频的噪声种子、字体子集、时区、语言、WebRTC 策略（关闭或只暴露代理 IP）。生成后写进账号配置并永久冻结。这样同时解决两个风险：克隆出来的多个账号指纹同源；同一个账号的指纹每次都不一样。如果用 rebrowser Chromium，要额外确认 Linux 平台特征的伪装方式，这一点上 Camoufox 更省心。
- 那四个配置（代理端点、人设包、bot token、API key）：统一放进一个权限 600 的实例配置文件，通过 scp 或腾讯云自动化助手（TAT）注入。缺任何一项，服务拒绝启动。
- state/ 账本和叙事记忆 SQLite：每台实例从空库初始化。
- SSH 主机密钥、/etc/machine-id、主机名：首次启动重新生成。
- 日志、shell 历史、git 凭据：做镜像前清空。

必须加的一道硬闸门（防止 VPS 本机 IP 碰到 X）：
1. 浏览器用专用系统用户运行。
2. 用 nftables 按用户 ID 限制其出口，只允许连环回地址和住宅代理的 IP:端口，其他一律丢弃；规则在首启时根据代理配置生成。
3. 每次启动浏览器前先通过代理查一次出口 IP，与预期不一致就不启动，并经 Telegram 告警。

操作流程：
1. 在最低规格的目标套餐（2核4G / 60GB）上打磨黄金机——镜像只能部署到系统盘不小于源盘的套餐上。
2. 跑一遍清理清单：停服务，删 profile、state、数据库、日志、密钥、主机密钥，清空 machine-id，关机，然后控制台「制作镜像」，按日期打版本号（如 golden-v20261023）。
3. 每开一个新号：用镜像开实例（跨地域用「跨地域复制」），注入实例配置，首启自动生成指纹和防火墙规则，自检通过后启用服务。
4. 日常代码更新用 git 拉取，不必重做镜像；只有系统或浏览器大版本升级才重做，浏览器版本变化会影响指纹，按批次灰度升级。
5. 每台实例定期快照，再把 profile、state/ 和 SQLite 备份到机器外——丢 profile 就要重新登录 X，这本身就是账号风险。

## 可直接下单的配置

主方案（黄金机和以后每台账号机都用）：
- 产品：腾讯云轻量应用服务器；地域：中国香港
- 镜像：操作系统镜像 Ubuntu Server 24.04 LTS（不选应用镜像、不选容器镜像）
- 规格：2核4G / 60GB SSD / 30M 峰值 / 1.5TB 月流量；流量包不买（超额约 1 元/GB，正常用不到）
- 购买时长：黄金机按月买；验证 2–4 周稳定后，克隆机按年买拿年付折扣
- 月成本：约 50–90 元/台（具体价格、新用户促销与续费价以下单页实时价为准）

备选：锐驰型 200Mbps 不限流量（约 40 元/月起，仅在有 4G 内存档时考虑）；4核8G 促销（约 88 元/月，只适合接受"以后所有克隆机都是 120GB 盘"的情况，续费价必须先核实）。

单个账号总成本 ≈ VPS 50–90 元/月 + 住宅代理（另购）。下单页需实时核实：各套餐价格、促销限制、续费价、锐驰型内存档位、流量计费方向、自定义镜像配额。
