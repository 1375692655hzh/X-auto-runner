## 1. 定位

把 x-auto-runner 培养成**联合运营者**：日常自主完成任务、保留完整反馈、定期接受评估，能力通过**版本迭代**提升——而不是一个"更高级的 Agent Loop"。

> 下一阶段的核心不是换框架，而是让现有 Loop 的每次成功、驳回、修改和发布结果都能产生**可审计的反馈**，并反过来改善选题和质量控制。

## 2. 铁律（不可妥协，讨论时不得绕过）

1. **创作隔离**：系统提示词永不决定写什么。Reflexion 只沉淀红线类缺陷（署名残留、主体缺失、事实错误），不沉淀"怎么写好看"——后者等于系统重新接管内容。
2. **主脑无权自升级**：提示词、评分权重、权限的任何变更必须走「版本提案 → 回归测试 → 人工审核 → 灰度」。主脑可以处理当前任务，不能据管理者一句话改造系统。
3. **反馈三层时间尺度**：
   - 即时（单任务内）：按反馈改当前稿、取消当前票、避开本次重复内容；
   - 短期（小时/天级，受控运营记忆）：影响后续候选排序、暂缓高风险类别；**不得**永久修改题材边界/名企标准/发布策略；
   - 定期（版本级）：反馈汇总、失败案例、改进建议，经审核后改规则。
4. **不引入多 agent 框架**（LangGraph/ADK/smolagents/AutoGen/BabyAGI/Voyager）。票据状态机 + 审批闸 + 审计日志已覆盖其最有价值部分；引入 = 重写全部，换不来新能力。
5. **实证成熟度 > 机械成熟度**：验收看真实运行证据（发了什么、被驳了什么、质量曲线），不看"能跑"。
6. **宁缺毋滥**：没有合格增量允许 0 条。"该不发时不发"是考试项——否则系统会学会用更多帖子刷表面产量。
7. **事实边界**：作者只准用数据站素材。"研究/递归补齐"只能补素材层（同事件官方确认、关键数字更新），不能借研究之名自由编事实；补后必须重过编辑审核，无法确认原结论成立就取消。

## 5. 阶段路线图

### 阶段一：资讯 auto 试运行闭环（当前，进入条件= P0 补齐）

1. 清理旧署名票，防历史稿混入（现场核实后执行）
2. **补全过期守卫**：发布前复查素材新鲜度（采集→发布时长）+ 同 story 事件状态；超阈或事件已反转则取消不强行发
3. **auto 质量日报**：每日 QQ 推送发布数 / 编辑打回数 / 打回原因分布（可先接进现有 20:30 报告，独立推送后置）
4. **结构化驳回标签**：QQ 驳回/改稿时带原因标签（选题不相关 / 主体不名企 / 无实质增量 / 事实错误 / 署名残留 / 不可独立阅读 / 重复 / 表达不自然）
5. 开启 auto（仅资讯原创；回评、互动继续 review），运行后逐条抽查

**出口验收**：新票能自动完成选题→成稿→审核→发布；失败有明确原因和恢复路径；管理者反馈能查到并进入定期材料。

### 阶段二：反馈闭环与定期考试（auto 稳定后 1–2 周）

1. 互关种子池：20–50 个同类账号入池（纯运营活，代码不改）
2. **定期考试**（周为单位）：目标完成率 / 选题质量（驳回原因而非仅采纳率）/ 成稿质量（一次通过、修改后通过、仍不合格）/ 任务执行力（故障恢复、卡住票处理）/ 反馈落实（已指出问题是否复发）/ 自主边界（越权、虚报完成、未经批准发布）
3. 运营研究环（人工版 Reflexion）：驳回标签统计 → 周报 → 人工调评分权重或红线条目
4. 回复质量抽查：reply 票固定比例转人工
5. LLM token 日审计 + 超阈值 QQ 告警

### 阶段三：扩大自治（有反馈数据之后，逐项验证、依次放开）

1. 回评、互访在 review 下验证质量后逐步放开
2. 动态任务分配：小时上限随信息增量和近 3 天采纳率浮动
3. structured_gate 从 shadow 转正（与真实采纳数据对账后）
4. 互动频率随收益数据调整

**顺序不可跳**：每次放开一个自治面，验收通过再放下一个。

## 8. 长期主杠杆：提示词/人设文档质量迭代（2026-11-09 确认）

### 定位

架构与功能搭完后，长期主要工作就是**提示词/人设文档的质量迭代**。现有资产已对齐：

- `prompts/` 四层结构：人设卡（L1，`config/persona-card`）→ L2 通用行为准则 → author-system / author-task → scenes 九个场景提示词
- `prompts/persona-gym/cases-g1~g3.json`：带 `pass_checks` 的离线评测用例
- `prompt_version()` 已在 auto 闸门强制版本一致

### 三条校准（与 §2 铁律对应，讨论时不得绕过）

**校准 1 — 优化对象三层分流：**

| 反馈类型 | 改哪里 | 性质 |
|---|---|---|
| 人设口吻不稳、红线犯错、风格漂移 | 人设卡 / L2 / author-system / 场景提示词 | 提示词，版本化迭代 |
| 题材驳回率高、评分误判、频率不当 | 评分权重、题材边界、预算阈值 | 配置参数，**不写入提示词** |
| 无互动对象、素材源差 | 种子池、数据站源 | 纯运营 |

**校准 2 — 社媒反馈是证据，不是目标函数：**
fxtwitter 拉的回复/引用/粉丝变化是定期考试的**输入证据之一**（哪类内容真实触达、读者反应、负面信号），由人或 MoA 解读后决定是否改、改哪层，**不自动改提示词**。直接用点赞/涨粉当优化目标必然 Goodhart 化（追热点、刷产量），撞碎"该不发时不发"。考试主口径仍是 §6 六维。

**校准 3 — 人设层可优化，写法层禁沉淀：**
人设卡（我是谁/口吻/立场/红线）随考核迭代是合理的；但"数据好的写法"不得练成模板/结构约束——人设卡中"历史表达样例仅供风格参考，不作结构约束"的边界在优化中永久有效（§2 铁律 1）。

### 双环考核流水线（铁律 2 的具体化）

```text
离线环：提示词新版本 → persona-gym 跑 cases（pass_checks）→ 回归测试
在线环：灰度上线 → 真实发布 → fxtwitter 拉社媒反馈 → 进入下次定期考核材料
                ↓ 考核不过
        降回旧版本 / 回 review 模式
```

gym 是回归测试的载体，社媒反馈是灰度的成绩单。
